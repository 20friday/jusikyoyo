# 종목 랭킹 상세카드 감정태그 일관성 수정

작성일: 2026-06-18

## 문제

상세카드의 감정태그(긍정/중립/주의/단순 언급)가 종목의 실제 코멘트·점수와 어긋난다.

- **일간:** 감정태그를 "기준일 하루치 감정 캐시"에서만 찾는다. 종목이 다른 날(예: LIG넥스원 6/16)
  데이터로 순위에 올라오면, 기준일(6/17)엔 감정이 없어 "단순 언급"으로 뜬다. 정작 종목의견엔
  "16% 급등…" 강한 긍정 코멘트가 있어 모순.
- **주간·월간:** "기간 감정 요약"(week_sentiment/month_sentiment)을 날짜별로 별도 캐시한다.
  이 요약이 순위 종목을 다 담지 못하거나(불완전) 날짜가 어긋나면 그대로 "단순 언급"이 뜬다.
  (실측: 주간 순위 10종목 중 5종목이 6/18 요약 캐시에 누락 → 단순 언급)

공통 원인: 감정태그가 "종목별 실제 감정"이 아니라 "특정 날짜/요약 캐시"에 의존.

## 데이터 사실

- `daily_reports.sentiment`(JSONB)에 **종목별로 status·intensity(강도 1~5)·reason이 매일 저장**돼 있다.
  (Haiku가 일간 분석 시 생성·캐시. 화면엔 강도 숨김.)
- 서버 `computeRanking`은 이미 `allReports`에 `sentiment` 컬럼을 함께 로드한다.

## 설계

### 1. 감정을 종목별 일간 감정에서 직접 산출 (서버)

`computeScored`에서 종목마다 그 종목이 등장한 날들의 `daily_reports.sentiment[name]`을 모아,
period별로 대표 감정을 고른다.

- **일간(day):** 그 종목이 마지막으로 등장한 날의 감정.
- **주간·월간(week/month):** 그 기간 중 **강도(intensity)가 가장 센 날**의 감정.
  강도가 같으면 **더 최근 날**. (= "그 기간 가장 강하게 다뤄진 분위기")

선택된 감정의 `status / intensity / reason / 날짜(sentimentDate)`를 RankedStock에 직접 실어 보낸다.
- 감정태그, 점수의 감정 가중치(nuanceScore), "분석 내용" 모두 이 값을 사용 → 한 종목 안에서 일치.
- 어느 등장일에도 감정 데이터가 없으면 `noSentiment=true` → "단순 언급" (이제 드뭄).

별도 주간/월간 요약(week_sentiment/month_sentiment)은 태그 계산에서 더 이상 사용하지 않는다.
(컬럼·생성 코드는 남겨두되 랭킹은 참조 안 함 → 안정성·AI 비용 절감.)

### 2. 생성 트리거 유지

최신 리포트 날짜의 일간 감정이 아직 캐시 안 됐을 수 있으므로, 클라이언트는 기존처럼
`/api/stock-sentiment?date=<최신리포트일>&period=day`를 1회 호출해 생성·캐시를 보장한 뒤
랭킹을 한 번 갱신한다. (과거 날짜는 대부분 이미 캐시돼 있음)

### 3. 날짜 표기 (클라이언트)

- 감정태그 근처: 일간 `"M월 D일 방송 기준"`(sentimentDate) / 주간 `"이번 주 종합"` / 월간 `"이번 달 종합"`
- "왜 순위에 올랐나요" 각 방송 줄: `"M/D · 방송명: ..."` (basis에 날짜 prefix)

## 영향 범위 / 비변경

- 점수 공식(꾸준함 60/누적 30/감정 ±20, 일간 기존식)은 그대로. 감정의 "출처"만 바뀜.
- 한국 단일 종목 필터, 순위 화살표 로직은 그대로.

## 검증 시나리오

- 일간: LIG넥스원 → 6/16 "긍정"으로 표시(현재 "단순 언급") + "6월 16일 방송 기준".
- 주간: 네이버·원익IPS·현대차·HD현대중공업·테크윙 → 단순 언급 사라지고 각자 실제 감정 표시.
- 단순 언급은 종목이 등장한 어느 날에도 감정이 없는 경우에만.
